# Item-owned additive affix growth (v0.71 integration)

Implements the reviewed v1 growth curve, **not** the optional old-range-floor v1b.
No new affix types, no base-equipment budget changes, no change to approved
lifesteal/legendary/Infinity/Return Ring mechanics. Save schema remains 6.

## Fixed source policy

`affix-level-budget.js` owns immutable coefficient version 1:

```
B(L) = 40 * 1.025 ** (min(L,100)-20)
A(L) = 14 + 3*min(L,100) + 2*B(L)
H(L) = 120 + 14*min(L,100) + 13*B(L)
D(L) = 105 + min(L,100) + 2*B(L)
qualityScale = [1, 1.04, 1.08, 1.12, 1.232]
atk range = round([3,6] * A(L)/154 * qualityScale)
hp range = round([20,40] * H(L)/920 * qualityScale)
armor range = round([3,6] * D(L)/205 * qualityScale)
```

Endpoints are integer, minimum 1. All other ordinary affixes retain the existing
quality-only ranges, including hit/crit/critDamage, 12 elemental fields,
lifesteal and luck. Only the source equipment level is read at generation;
wearer level, talents, other equipment and temporary buffs are never inputs.

Q3 at levels 1/10/20/50/100:
- ATK: 1–3 / 2–5 / 3–7 / 7–14 / 19–39
- HP: 11–22 / 16–32 / 22–45 / 47–93 / 128–257
- Armor: 3–5 / 3–6 / 3–7 / 5–11 / 13–26

`sourceRange` is canonical `{model:'level-quality-v2',quality,sourceLevel,min,max}`.
The established `quality` key means **source quality**, not recipient rarity;
it is intentionally not duplicated into an ambiguous second quality field.
The affix's existing `value` is the fixed raw integer roll. No extra float
percentile needs to be stored. UI colors use the recorded own range and the
source tooltip distinguishes old items and immutable level-owned sources.

## Compatibility and atomicity

- Existing `quality-v1` ranges and raw values stay valid, never auto-converted.
  Two-argument `makeAffixSourceRange(def,q)` deliberately constructs a legacy
  quality-only range for archived fixtures and explicit historical provenance.
  New generators must supply `{stat,sourceLevel}` as the third argument.
- New ordinary, merchant, forge, drop and legendary generators use v2. A
  legendary ordinary affix uses source quality 4; zero-affix primal core stays 0.
- Same-slot donor replacement copies raw value and the complete sourceRange.
  High-level sources can still transfer to low-level items: approved raw
  inheritance has not gained an undocumented gate or recipient scaling.
- Value wash uses the recorded source range; full wash creates ranges from the
  recipient item's current own level/quality and explicitly replaces sources.
- New pending reforge records use operation rule 7 (not save schema 7). Existing
  rule-6 paid records remain valid and resolve their frozen values with zero
  RNG and no new charge. Full-wash validation chooses the rule-specific table;
  corruption/downgrading a new full-wash transaction to old rule 6 is rejected.
- Enhancement still scales base stats only. Divine still multiplies base and
  ordinary raw affix contribution once by 1.1, with no writeback compounding.
- `fixtures/v070-affix-pending-v6.json` was generated by exact old HEAD
  `9f56c77996038f929d390a35ac48167250f1475d`: old value/replace/all paid
  transactions with divine targets. It is a legacy save fixture, not a new-game
  starter-equipment prescription.

`node affix-level-growth-tests.mjs`:
10,000 level/quality/stat ranges; 2,000 real five-race generated items; exact
numeric anchors; cap100; rating invariance; inherited legendary HP282 on a
level1 common carrier; value/full wash distinctions; divine and enhancement;
JSON/cross-realm saves; old paid accept/keep without RNG; 15 corruption cases;
merchant/forge propagation. This test also passes in the parent's integrated
empty-inventory new-game tree, not just the legacy worktree.

Existing focused affix-source/production, multi-affix, reforge atomicity,
inheritance, same-type, divine, legendary factory, current-save, equipment
fusion, formal enhancement, Return Ring healing and Infinity combat tests pass.
Expected assertions that formerly hardcoded *new* range model quality-v1 or
pending rule6 were updated, while independent exact-old fixtures preserve the
compatibility oracle. No balance claim relies solely on these assertions.

`affix-source-ui-tests.cjs` uses actual app code with DOM mocks (not screenshot
QA). It covers v2 level100 HP257 inherited on a level2 carrier, correct range
128–257/source label/divine282.7, value-wash failed-write retry without reroll,
reload/accept, alongside the previous v1 HP45 compatibility scenarios.

`node tools/affix-first-drops-probe.mjs <verified-old-repo> [1000]` compares real
old and new `item()` factories with identical PRNG draws. It verifies baseline
HEAD and clean `dist`, same template/stat selections, real A1 level3–7, Q0/Q1
conditional 65:28 distribution, first three received items, empty-slot fill.
At 1,000 trajectories/race, third-drop mean physical DPS delta spans
−0.76% to −1.18%; mean physical EHP delta −0.49% to −0.55%; median deltas are 0.
This is a generated-loot distribution and heroLv1/armor12 static probe, **not**
a natural earning trajectory or a dungeon-clear claim. The separate natural
progression owner covers actual integrated startup outcomes.

High-end four-affix/max-roll stress remains a known balancing consideration:
new Lv100 ATK/HP/armor can improve combined physical EHP roughly 33–42% over
old fixed affixes, not merely the ~3% value of a single line. Existing core,
percentage healing and lifesteal multiply those benefits. Evaluate with the
new enemy pressure curve and actual skill host; do not scale rating affixes
or silently suppress approved core effects to force identical race outcomes.

Release assets use content-hashed immutable namespaces; the new imported
module participates automatically. Root integration/publishing remains the
parent task's responsibility. No remote push or deploy was performed here.

files, 2,784 resource URLs and 8,636 dependency edges, including the new range
